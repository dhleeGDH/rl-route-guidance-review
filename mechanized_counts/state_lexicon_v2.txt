# Sentence-selection lexicon, second version.
#
# WHAT CHANGED FROM state_lexicon.txt AND WHY. The first version implemented the positive half of
# Section III-A, the clause naming what a forecast-conditioned state contains, and nothing else.
# Section III-A carries two further clauses that the first version left unimplemented, and both
# bear on which sentences are evidence rather than on how evidence is classified. This version
# implements them. It also implements the clause that puts a forecast into the state as a feature,
# which the first version read only through sentences carrying the word state.
#
# Both versions are kept and both counts are reported. Nothing here was written after comparing a
# count to the recorded one; each addition quotes the Section III-A sentence that licenses it.
#
# The classification rule in experiments/recode_state_field.py is untouched by either version.

[SELECT_STATE]
# "The state s_t at decision step t contains two kinds of information." (Sec. III-A)
\bstates?\b
\bstate[- ](?:space|vector|representation|variables?|features?|definition)\b
\bs_?t\b
# "an observation window that learning has shaped into a predictive summary" (Sec. III-A)
\bobservations?\b
\bobservation[- ]space\b
# "Such a forecast enters the state as a feature" (Sec. III-A). ADDED IN THIS VERSION: the first
# version reached this clause only through the word state, and a study that lists its features in
# a table or defines them as link attributes never uses that word in the same sentence.
\bfeature vectors?\b
\binput (?:vector|layer|space|features?|to the (?:network|agent|policy|actor|critic))\b
\b(?:link|edge|road|node)[- ](?:attributes?|features?)\b
\battributes? (?:of|for) (?:each |every |the )?(?:link|edge|road|segment|node)\b
\bfeatures? (?:of|for) (?:each |every |the )?(?:link|edge|road|segment|node)\b
\b(?:is|are) (?:used as|taken as|fed (?:in)?to|passed to) the (?:state|input|network|policy)\b

[SELECT_ROLLOUT]
# "or is generated by a model rollout at planning time" (Sec. III-A)
\broll-?outs?\b
\brolls? out\b
\bplanning (?:horizon|time|step)\b

#
# --- ADDED IN THIS VERSION ---------------------------------------------------------------------
# "Second, an implicitly forecasting value function does not meet the criterion. A Q-function
#  trained under time-varying dynamics encodes an expected future cost, taken over the training
#  distribution rather than the episode at hand." (Sec. III-A)
# A sentence whose prediction is of a value, a return, a reward, or an action reports the learning
# machinery, not the traffic conditions the state carries, and Section III-A excludes it by name.
predict\w*\s+(?:the\s+|this\s+|a\s+|an\s+)?(?:expected\s+|discounted\s+|estimated\s+|best\s+|optimal\s+)?(?:q[- ]?values?|q[- ]?function|value|values|state[-–\s]?action value|return|returns|reward|rewards|action|actions|policy)\b
\b(?:predicted|predicts)\s+(?:by\s+)?(?:the\s+)?(?:q|value|critic|network|action|policy)\b
\bvalue prediction\b
\bpredicted (?:q|value|action|reward|return)\b
# "the state transition probability matrix" is a model of dynamics, not a forecast in the state.
predict\w*[^.]{0,45}\bstate[- ]?transitions?\b
predict\w*\s+(?:the\s+|its\s+)?next state\b
predict\w*[^.]{0,25}\btransition probabilit\w*
#
# "The decision-time rollout counts as predictive when its unrolling is conditioned on the
#  episode's observed state and advanced through a forecast." (Sec. III-A)
# A rollout buffer holds training transitions and is not unrolled at decision time.
\broll-?out (?:buffer|length|horizon|steps?|size)\b
\bcollect\w*\s+roll-?outs?\b
\broll-?outs?\s+from the simulator\b
#
# "when the mention of prediction is negated" (the rule's negative clause, Sec. III-A). The
# published rule catches the forms it was written against; these are the further negations the
# full texts use.
\b(?:do|does|did|can|could|will|would|is|are|was|were)\s+not\s+\w{0,12}\s*(?:predict|forecast|anticipat)\w*
\b(?:without|no|neither|nor)\s+\w{0,12}\s*(?:predict|forecast|anticipat)\w*
\brather than\s+\w{0,12}\s*(?:predict|forecast|anticipat)\w*
